# فحص العهدة — مصفوفة التسليم

```bash
php tools/فحص-العهدة/run.php
```

٢٩ دعوى تُشغّل `SCH_Custody::record()` **الحقيقيّة** فوق `$wpdb` مزيّف —
لا خادم ولا قاعدة ولا ووردبريس.

## لماذا وُجدت

الفحص الشامل كشف أن `validate()` تشترط `picker` (مفتاحًا من قائمة
المخوَّلين) في نقاط التسليم الثلاث لكل طفل روضة أو ابتدائي — **ولا واجهة
تُرسل هذا المفتاح**. فكل مسح خروج لطفلٍ صغير كان يُرَدّ بـ`picker_required`،
وعهدته تبقى `at_school` طوال الليل وأبوه يرى في تطبيقه «في المدرسة».

وكشف عطلًا مقابلًا: تحويل وجهة راكب الباص إلى `on_bus` كان يُلغي فحص
`may_pick_up()` كلّه — **فيصير نداء الانصراف بابًا خلفيًّا على إنفاذ
`can_pickup`** لكل طالبٍ مشترك بالنقل.

المصفوفة الآن مقفلة بدعاوى، لا بذاكرةٍ ولا بتعليق.

## ما تُثبته

| القسم | الدعوى |
|---|---|
| ① | خروج نهاية الدوام يمرّ **لكل المراحل بمسح الحارس وحده** — كما في `WORKFLOW.md` §2 |
| ② | الخروج المبكر يُرفض بلا مستلم · ويُرفض بغير مخوَّل · ويمرّ بمخوَّل — والاسم والسبب يُكتبان، والإشعار يحمل الاسم |
| ③ | النزول من الباص يُرفض للصغار بلا تأكيد، ويمرّ للكبار — ومن ذُكر اسمه فلا بدّ أن يكون مخوَّلًا |
| ④ | راكب الباص: مسح الحارس وحده ⟵ `on_bus`، واستلام أبيه ⟵ `home`. **وغير المخوَّل يُرفض ولو كان مشتركًا** |
| ⑤ | الانتقال الممنوع يُرفض **ويُسجَّل** — لا يُتجاهل بصمت |
| ⑥ | `client_uuid` المكرّر يُعيد النتيجة الأولى بلا سجلٍّ ثانٍ |
| ⑦ | `find_by_badge()` لا تقبل `academic_no` ولا `student_no` — الرقم مطبوع نصًّا على وجه البطاقة، و`WORKFLOW.md:352` يمنعه |
| ⑧ | طالبٌ بلا مخوَّلٍ واحد: خروجه المبكر يُرفض برسالةٍ صريحة لا بخانة كتابة |

## أنها تكشف فعلًا

على الشفرة **قبل** الإصلاح تفشل **١٣ دعوى** من ٢٩ — بينها الأربع الأولى
(لا يخرج طفل صغير من البوابة) والاثنتان في ④ (الباب الخلفي على `can_pickup`).

```bash
git stash -- school-system/modules/custody/class-custody.php
php tools/فحص-العهدة/run.php     # نجح 16 · فشل 13
git stash pop
php tools/فحص-العهدة/run.php     # نجح 29 · فشل 0
```
