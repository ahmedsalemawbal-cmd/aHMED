# فحص المال

```bash
php tools/فحص-المال/run.php
```

٤٣ دعوى تُشغّل `SCH_Finance::issue_invoice()` و`record_payment()`
**الحقيقيّتين** فوق `$wpdb` مزيّف — بلا خادم وبلا قاعدة.

## لماذا وُجدت

النظام يُجهَّز لمدرسةٍ تُفوتر أهاليها. و**خطأ الشاشة يُرى ويُشتكى منه؛
خطأُ الريال لا يراه أحد حتى تُراجَع الحسابات آخر السنة** — وحينها لا يُعرف
متى بدأ ولا كم فاتورةً أصاب.

والطبقة اليوم **صحيحة**: الأربع عمليات المالية كلّها داخل معاملة مع
`SELECT … FOR UPDATE`، والخصم قبل التقسيم، والكسر في الدفعة الأولى.
والدعاوى هنا لا تُصلح شيئًا — **تُبقيه كذلك**.

## ما تُثبته

| القسم | الدعوى |
|---|---|
| ① | **الخصم نسبة لا مبلغًا ويُطبَّق قبل التقسيم** · والنسبة فوق المئة تُقصّ · والسالبة لا تزيد المستحقّ |
| ② | **الكسر في الدفعة الأولى** لا الأخيرة · و**ستّون تقسيمًا مختلفًا** (٢–٤ أقساط × خمسة مبالغ × أربع نسب): **لا قرش يُخلَق ولا يضيع** |
| ③ | **تقسيط المدرسة امتيازٌ يُمنَح**: يُرفض بلا سببٍ مكتوب، ويُرفض ممّن لا يملك `sch_grant_installments` · والدفعة الكاملة وتابي وتمارا قسطٌ واحد مهما طُلب |
| ④ | **الذرّية**: فشلُ القيد المحاسبيّ يتراجع بالفاتورة والأقساط معًا — فلا تبقى فاتورةٌ بلا قيد ولا أقساطٌ يتيمة |
| ⑤ | فاتورةٌ واحدة لكل خطةٍ في السنة · وطالبٌ أو خطّةٌ غير موجودة تُرفض |
| ⑥ | الدفع: يُرفض ما تجاوز المتبقّي · والصفر · والسالب · ولا دفعة على مسدَّدة · والأقساط تُغلق بالترتيب |
| ⑦ | **`paid` تساوي مجموع صفوف الدفعات بالقروش** — لا انزياح |

## وأنها تكشف فعلًا

بكسر القاعدتين المركزيّتين في `class-finance.php`:

```bash
# الكسر إلى الدفعة الأخيرة بدل الأولى  →  ٣ دعاوى تسقط
# الخصم لا يُطبَّق قبل التقسيم        →  ٤ دعاوى تسقط
```

## وعطلٌ كشفته أثناء بنائها

`class-finance.php:106` كان:

```php
$mode = in_array($d['pay_mode'] ?? 'full', […], true)
    ? (string) $d['pay_mode']   // ← غير محميّ
    : 'full';
```

الـ`??` تحمي **الفحص** ولا تحمي فرعه: حين يغيب المفتاح تمرّ `'full'` في
`in_array` ثم يُقرأ `$d['pay_mode']` غير الموجود — **تحذيرُ PHP مع كل
إصدار فاتورةٍ لا تُذكر فيها طريقة الدفع، وهو الحال الافتراضيّ**. يصمت في
الإنتاج و`WP_DEBUG` مطفأ، ويملأ السجلّ حين يُشتغَّل. وأُصلح.

## ما لا تغطّيه

- **التسابق الحقيقيّ** — `FOR UPDATE` موجودة في الشفرة، وإثبات أثرها يحتاج
  MySQL بجلستين متزامنتين. مكانه **بروفة التشغيل**.
- **ميزان المراجعة ودفتر الأستاذ** — طبقةٌ أخرى (`SCH_AutoPost` مُستبدَلة
  هنا بمزيّفٍ يلتقط النداءات).
