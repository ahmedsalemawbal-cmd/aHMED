# نظام المدرسة — School System

إضافة ووردبريس لإدارة مدرسة واحدة إدارةً كاملة: الطلاب وأولياء الأمور والشعب،
النقل المدرسي بتتبّع حي، الحضور، الأكاديمي، المالية والمحاسبة، الموارد البشرية،
العيادة والخدمات — ومعها **ستّ واجهات مستقلة** وREST API للتطبيقات.

**النسخة:** 8.3.0 · **يتطلّب:** WordPress 6.4+ · PHP 8.2+ · MySQL 5.7+ (InnoDB)

---

## ما الذي يُبنى هنا فعلًا

| الواجهة | المسار | لمن |
|---|---|---|
| الداشبورد | `/dashboard` | الإدارة — 47 قسمًا |
| بوابة الدخول الموحّدة | `/login` | الجميع، ثم يُوجَّه كلٌّ لواجهته |
| تطبيق ولي الأمر | `/app` | أولياء الأمور |
| تطبيق المعلم | `/teacher` | المعلمون |
| تطبيق السائق | `/driver` | سائقو الباصات |
| تطبيق البوابة | `/gate` | حرّاس البوابة |
| تطبيق الطالب | `/student` | الطلاب |
| REST API | `school/v1` | التطبيقات (JWT) |

الداشبورد **خارج لوحة ووردبريس تمامًا** — مستند كامل من `frontend/views/layout.php`،
بلا قالب ثيم ولا شريط أدمن. وأصحاب أدوار `sch_*` ممنوعون من `/wp-admin`.

## التركيب

### على خادم حقيقي

1. ارفع الـZIP من **الإضافات ← أضف جديدًا ← رفع الإضافة**، أو انسخ مجلد
   `school-system/` إلى `wp-content/plugins/`.
2. فعّل الإضافة. التفعيل يُنشئ **68 جدولًا** والأدوار الأربعة عشر ومفتاح التوقيع.
3. افتح `/dashboard/settings` وتأكد أنه **لا جدول ناقص** (الشاشة تُبلّغ صراحةً).
4. **الروابط الدائمة شرط**: الإعدادات ← الروابط الدائمة ← أي صيغة عدا «عادي».
   كل المسارات أعلاه قواعد توجيه لا معاملات استعلام.
5. إن كان الخادم **Nginx**: راجع «حماية ملفات الطلاب» أدناه — الأمر ليس اختياريًا.
6. إن كان عليك **LiteSpeed Cache**: استثنِ `/dashboard` و`/app` وبقية الواجهات
   يدويًا. الإضافة تُرسل ترويسات منع الكاش، والاستثناء طبقة ثانية.
7. **اجعل لغة ووردبريس عربية** (الإعدادات ← عام ← لغة الموقع). بلا حزمة اللغة
   العربية تُعرض **التواريخ بالإنجليزية** داخل واجهة عربية — النصوص نفسها لا
   تتأثر لأنها عربية في المصدر.

### للتطوير محليًا

```bash
./dev.sh up        # ووردبريس + MySQL + الإضافة + بيانات تجريبية  (~3 دقائق)
./dev.sh sync      # بعد كل تعديل — أقل من ثانية
./dev.sh audit     # php -l على كل ملف + audit.py
./dev.sh shots     # صورة لكل شاشة + تقرير أخطاء
./dev.sh reset     # من صفر
./dev.sh logs      # متابعة سجل أخطاء PHP
```

يبني لك مدرسة كاملة: ٤٠ طالبًا · ٢٠ ولي أمر · ١٢ موظفًا بكل دور · مسار وباص ·
٤٨٠ سجل حضور — **لأن العطل لا يظهر على جدول فارغ**. وحسابات كل الأدوار بكلمة
مرور واحدة معروفة (`Test!12345`)، وأسماء الدخول في `~/.sch-dev/accounts.json`.

## قبل أي تسليم

```bash
python3 audit.py     # يجب أن يخرج «نظيف»
./build.sh --patch   # يرفع الرقم، يفحص، ثم يبني الـZIP
```

`build.sh` **لا يبني قبل أن يمرّ `php -l` و`audit.py`** — فما لا يُفحص لا يُسلَّم.
ويرفع `SCH_VERSION` لأن رقم الإضافة هو إشارة الترقية: عليه تُفرَّغ طبقة الكاش
وتُعاد قواعد التوجيه وتُزامَن الأدوار.

### `audit.py` — 32 فحصًا

يمسك ما تعلّمناه من أعطال حقيقية: قالب `if(…):` بلا `endif` (صفحة بيضاء) ·
عمود مكرر في `CREATE TABLE` (الجدول لا يُنشأ بصمت) · عمود يُستعلم عنه ولا وجود
له · نموذج بلا نونس · نافذة بلا زر يفتحها · صنف CSS معرَّف مرتين بخصائص تخطيط ·
رمز بلا تعريف · فعل بلا معالج · صلاحية بلا دور · مورد من CDN خارجي · وغيرها.

```bash
python3 audit.py --list        # أسماء الفحوص
python3 audit.py -o CSS_DUP_LAYOUT
python3 audit.py --strict      # التحذير يُفشِل أيضًا
python3 tools/audit-selftest.py   # كل فحص يُثبت بإحداث عطله ثم إزالته
```

**الاختبار الذاتي هو ما يجعل الفحص ذا قيمة.** فحص صامت لا يُعرَف: هل صمت لأن
الكود سليم أم لأنه معطوب؟ ثلاثة فحوص هنا كانت معطوبة صامتة حتى اختُبرت هكذا.

### القواعد التي تحكم الكود

- **لا SQL خارج `modules/`.** الشاشات والـAPI تنادي طبقة البيانات فقط.
- **كل استعلام عبر `$wpdb->prepare()`.** بلا استثناء.
- **كل فعل في الداشبورد** يمرّ بـ`handle_post()`: نونس ثم صلاحية ثم المعالج.
  إضافة فعل = سطر في `actions()` + دالة `do_*`. لا مسار ثانٍ.
- **كل قسم** = سطر في `SECTIONS` + ملف في `frontend/views/`.
- **رموز التصميم `--sch-*` بيتها `assets/shared-ui.css`** وحده
  (و`parent.css`/`admin.css`/طبقة الداشبورد استثناءات موثّقة).
- **عائلة خط واحدة** — تُبدَّل من سطرين في `shared-ui.css`.
- **الخصائص المنطقية فقط** (`margin-inline-start` لا `margin-right`) — الواجهة RTL.
- **`assets/dashboard.css` مولَّد.** عدّل الجزء في `assets/dashboard/` ثم
  `python3 tools/css-split.py build` (و`./dev.sh sync` يفعلها عنك).
  الترتيب في `_order.txt` **يحمل معنى**: الطبقة اللاحقة تطمس ما قبلها.
  ويمسك `CSS_PARTS_STALE` أي مولَّد لا يطابق أجزاءه، وأي جزء خارج الترتيب.

اقرأ `CLAUDE.md` قبل أي عمل: فيه سبب كل قرار، ومعه `WORKFLOW.md` لسير عمل
الطالب والنقل، و`REDESIGN_v5.md` لنظام التصميم.

## الأمان

- **JWT**: مفتاح 64 بايتًا يُولَّد تلقائيًا، ويُرفض أي مفتاح أقصر من 32.
  `access_token` ١٥ دقيقة، و`refresh_token` **يُدوَّر عند كل تحديث** —
  والمستهلك مرفوض.
- **حدّ المحاولات**: خمس محاولات لكل (اسم + IP) ثم قفل ربع ساعة — على شاشة
  الداشبورد **وعلى `/auth/login` معًا**.
- **الصلاحيات تُفحص في الخادم دائمًا**: `current_user_can()` + `SCH_Perms::may()`.
- **ملفات الطلاب** في `uploads/sch-private/` — لا تُقرأ من القرص قبل الإجابة
  عن «هل يحق لهذا الشخص رؤيتها؟»، والمسار محصور بـ`realpath`، والنوع يُفحص من
  المحتوى لا الامتداد، و**EXIF يُمسح** من كل JPEG (قد يحمل إحداثيات منزل الطالب).

### حماية ملفات الطلاب على Nginx

الحماية تُكتب كملف `.htaccess` داخل `uploads/sch-private/` — **وNginx لا يقرأ
`.htaccess` إطلاقًا**. على Nginx أضف في إعداد الموقع:

```nginx
location ~* /wp-content/uploads/sch-private/ {
    deny all;
    return 403;
}
```

بلا هذا تصير مستندات الطلاب وصورهم مفتوحة برابط مباشر لمن يعرفه.

## واجهة التطبيقات (REST)

```
POST school/v1/auth/login      { username, password, device_id }
POST school/v1/auth/refresh    { refresh_token }   ← يُرجع رمزًا جديدًا
GET  school/v1/me
GET  school/v1/me/children
GET  school/v1/students/{id}/today      ← نداء واحد يجمع شاشة ولي الأمر
GET  school/v1/driver/trip
POST school/v1/driver/trip/{id}/scan    ← يحمل client_uuid (لا تكرار)
```

المصادقة `Authorization: Bearer <access_token>`. كل مسار له `permission_callback`
حقيقي؛ والمساران المفتوحان (`login`/`refresh`) يتحققان داخليًا.

## الأدوار

| الدور | النطاق |
|---|---|
| `administrator` | كل شيء |
| `sch_principal` | مدير المدرسة |
| `sch_deputy` | وكيل الشؤون التعليمية |
| `sch_supervisor` | مشرف مرحلة |
| `sch_counselor` | أخصائي اجتماعي |
| `sch_teacher` | فصوله وطلابه وموادّه |
| `sch_accountant` | المالية — بلا وصول للدرجات |
| `sch_hr` | الموارد البشرية والعمليات |
| `sch_transport_supervisor` | الباصات والمسارات والرحلات |
| `sch_driver` | رحلته الحالية وطلابها فقط |
| `sch_guard` | البوابة |
| `sch_content` | المحتوى التعليمي |
| `sch_guardian` | أبناؤه فقط |
| `sch_student` | بياناته فقط |

**الدور قالب لا قيد**: من ليس له صف في `sch_user_perms` يعمل بصلاحيات دوره.
والصلاحيات المخصصة **طبقة فوق** فحص الدور لا بديلًا عنه، ببُعدين: «ماذا يرى»
و«على مَن» (كل المدرسة · مرحلته · فصوله).
