# بريد أصول البناء — تطبيق ويندوز

نسخة سطح المكتب من نظام بريد الموظفين الموجود على الموقع. التطبيق **بوابة
بريد فقط**: يُنزَّل، يُثبَّت، ويفتح شاشة دخول فيها حقلان — البريد وكلمة المرور.
بعد الدخول يجد الموظف صندوق بريده وحده: لا لوحة موظفين، ولا عروض أسعار، ولا
أي جزء آخر من بوابة الموقع.

```
تنزيل OsoulMail-Setup.exe  →  تثبيت تلقائي  →  بوابة الدخول  →  صندوق البريد
```

---

## ما الذي يفعله التطبيق

| | |
|---|---|
| **بوابة الدخول** | البريد وكلمة المرور فقط. خوادم Hostinger معبّأة مسبقًا. |
| **الموظفون المعتمدون** | الدخول مقصور على نطاق الشركة، والتحقق النهائي من خادم البريد نفسه. |
| **صندوق البريد** | المجلدات، الوارد، المرسل، المسودات، المحذوفات، المزعج + أي مجلد خاص. |
| **القراءة** | عرض HTML آمن، صور مضمّنة، مرفقات تُفتح أو تُحفظ. |
| **الكتابة** | إنشاء، رد، رد على الجميع، تمرير، نسخة ومخفية، مرفقات، توقيع. |
| **الترتيب** | تمييز بنجمة، تعليم كغير مقروء، نقل بين المجلدات، حذف. |
| **البحث** | بحث على الخادم في المرسل والموضوع والنص. |
| **الإشعار** | إشعار ويندوز عند وصول رسالة + عدّاد على أيقونة شريط المهام. |
| **المظهر** | عربي RTL، سمة داكنة وفاتحة، خط Cairo مضمّن (يعمل بلا إنترنت). |

اختصارات لوحة المفاتيح: `C` رسالة جديدة · `R` رد · `A` رد على الجميع ·
`F` تمرير · `S` تمييز · `U` غير مقروءة · `J`/`K` تنقّل · `Delete` حذف ·
`Ctrl+K` أو `/` بحث · `F5` تحديث.

## للموظف

1. نزّل `OsoulMail-Setup-1.0.0.exe` من مسؤول النظام.
2. شغّله — يُثبَّت خلال ثوانٍ ويفتح مباشرة (لا يحتاج صلاحيات مدير).
3. اكتب بريدك وكلمة مروره، ثم **دخول إلى بريدي**.

اختصار على سطح المكتب وفي قائمة ابدأ باسم **بريد أصول البناء**.

> كلمة المرور هي كلمة مرور صندوق البريد نفسها. لا يوجد تسجيل ذاتي ولا استعادة
> كلمة مرور داخل التطبيق — الحسابات يُنشئها مسؤول النظام.

## لمسؤول النظام

### بناء المُثبِّت

يُبنى على **ويندوز** (بناء NSIS على لينكس يحتاج Wine):

```bash
npm install
npm run dist          # ← dist/OsoulMail-Setup-<version>.exe
```

المُثبِّت بنقرة واحدة، لكل مستخدم (بلا UAC)، ويشغّل التطبيق بعد التثبيت.

### الضبط بلا إعادة بناء — `policy.json`

انسخ `policy.example.json` باسم `policy.json` إلى أحد الموضعين:

- `%LOCALAPPDATA%\Programs\osoul-mail-desktop\resources\policy.json` (لكل التثبيت)
- `%APPDATA%\Osoul Mail\policy.json` (لمستخدم واحد)

```jsonc
{
  "allowedDomains": ["osoulalbinaa.com"],  // [] = أي نطاق
  "rosterUrl": "",                          // تحقق اختياري من كشف الموظفين
  "allowAdvancedServers": true,             // إظهار "إعدادات الخادم المتقدمة"
  "refreshSeconds": 120,                    // 0 = الاعتماد على IDLE فقط
  "pageSize": 50,

  "imapHost": "imap.hostinger.com", "imapPort": 993,
  "smtpHost": "smtp.hostinger.com", "smtpPort": 465
}
```

### طبقات بوابة "الموظفين المعتمدين"

1. **النطاق** — لا يُقبل بريد خارج `allowedDomains`.
2. **الكشف** (اختياري) — إن ضُبط `rosterUrl` نادى التطبيق
   `GET <rosterUrl>?email=...` وتوقّع `{"approved": true|false}`؛ الرد `false`
   يمنع الدخول. تعذُّر الوصول للخادم لا يمنع الدخول لأن الطبقة الثالثة هي
   الفاصل.
3. **خادم البريد** — تحقق IMAP و SMTP حقيقي. إيقاف صندوق البريد على الخادم
   يمنع الدخول فورًا دون أي إجراء داخل التطبيق.

## الأمان

- **كلمة المرور** تُشفَّر بـ DPAPI عبر `safeStorage`: مربوطة بحساب المستخدم على
  الجهاز، فنسخ الملف إلى جهاز آخر لا يفيد. لو تعذّر التشفير لم تُحفظ كلمة
  المرور إطلاقًا، ويُعطَّل خيار "إبقائي مسجلًا للدخول".
- **نافذة العرض** تعمل بـ `sandbox` و `contextIsolation` بلا Node، وكل عملية
  شبكة أو قرص تمرّ عبر قائمة IPC صريحة في `preload.js`.
- **محتوى الرسائل** يُنظَّف في العملية الرئيسية (سكربتات، `on*`، `javascript:`،
  إطارات) ثم يُعرض داخل إطار معزول بلا سكربتات — طبقتان لا واحدة.
- **الصور الخارجية** محجوبة افتراضيًا فلا يعرف المُرسِل أنك فتحت رسالته؛
  الصور المضمّنة (`cid:`) تُدرج داخل الصفحة فتظهر الرسالة كاملة بلا أي طلب
  خارجي. زر "عرض الصور" يرفع الحجب لرسالة واحدة، والإعدادات ترفعه دائمًا.
- **الروابط** داخل الرسائل تُفتح في المتصفح الخارجي، ولا تُفتح نافذة تطبيق
  جديدة أبدًا، ولا تُقبل إلا `http`/`https`/`mailto`.
- **سياسة أمن المحتوى** تمنع أي اتصال شبكي من الواجهة (`connect-src 'none'`).

## البنية

```
src/
  main/         العملية الرئيسية (Node)
    main.js       دورة حياة التطبيق والنافذة وبروتوكول osoul://
    ipc.js        كل نقاط التخاطب مع الواجهة
    session.js    بوابة الدخول وجلسة الموظف
    imap.js       جلسة IMAP: اتصال واحد + طابور تسلسلي + تفكيك MIME
    smtp.js       بناء الرسالة وإرسالها وحفظ نسخة مطابقة في المرسل
    store.js      خزنة كلمة المرور (DPAPI) والإعدادات
    sanitize.js   تنظيف محتوى الرسائل
    config.js     السياسة الافتراضية وقراءة policy.json
  preload/
    preload.js    سطح التخاطب المسموح للواجهة (قائمة صريحة)
  renderer/       الواجهة (بلا أي إطار عمل — سرعة الإقلاع أولًا)
    index.html
    css/app.css   نظام التصميم المنقول من نسخة الويب
    js/           app · login · mail · compose · settings · util · icons
test/             خوادم IMAP و SMTP وهمية + أربع مجموعات اختبار
```

### لماذا اتصال IMAP واحد

خوادم الاستضافة (Hostinger منها) تحدّ عدد اتصالات IMAP المتزامنة. التطبيق
يفتح اتصالًا واحدًا يُعاد استخدامه طوال الجلسة وتمرّ عليه كل الأوامر
بالتسلسل، ويعيد الاتصال تلقائيًا عند الانقطاع. كذلك لا تُحمَّل أجسام الرسائل
عند سرد القائمة — الترويسات فقط — والجسم يُطلب عند الفتح، والمرفق عند الضغط
عليه وحده.

## الاختبارات

```bash
npm test              # الأربع مجموعات
npm run test:imap     # جلسة IMAP مقابل خادم مصغّر حقيقي
npm run test:smtp     # بناء الرسالة والإرسال وحفظ نسخة المرسل
npm run test:vault    # خزنة كلمة المرور والإعدادات
npm run test:e2e      # التطبيق كاملًا: دخول → قراءة → رد → خروج
```

الاختبارات تشغّل خادمي IMAP و SMTP مصغّرين على `127.0.0.1` — لا تحتاج إنترنت
ولا صندوق بريد حقيقي. تغطي: المجلدات المميزة، الترقيم، البحث، فك ترميز
الترويسات، `base64` و `quoted-printable`، تحويل `windows-1256` إلى UTF-8،
الصور المضمّنة، المرفقات بأسماء عربية، رفض بيانات الدخول الخاطئة، وحجب
السكربتات في محتوى الرسائل.

> على لينكس بلا حلقة مفاتيح سطح مكتب يتخطى اختبار `e2e` فحصَي حفظ كلمة المرور
> ويتحقق بدلًا منهما أنها **لم** تُكتب. في ويندوز يتوفر DPAPI دائمًا فتُنفَّذ
> الفحوص كاملة.
