# توقيع التطبيق لويندوز

## لماذا

ويندوز 11 فيه **التحكم الذكي في التطبيقات** (Smart App Control). حين يكون
مفعّلًا يحظر أي ملف تنفيذي لا يحمل توقيع ناشر معروف، **وبلا زر تجاوز** —
بخلاف تحذير SmartScreen القديم الذي فيه «شغّل على أي حال».

فالتوقيع ليس تحسينًا تجميليًا: بدونه لا يُثبَّت التطبيق على تلك الأجهزة
إطلاقًا.

## الخياران

| | خدمة Microsoft للتوقيع | شهادة PFX تقليدية |
|---|---|---|
| التكلفة | ~‏١٠ دولار شهريًا | ~‏٢٠٠–٧٠٠ دولار سنويًا |
| رمز صلب (USB) | لا يحتاج | يحتاج منذ ٢٠٢٣ |
| السمعة لدى ويندوز | فورية | تُبنى بالتنزيلات (EV فورية) |
| يعمل مع البناء الآلي | نعم | نعم |

الأرخص والأسهل لشركة واحدة هو الأول:
[Azure Trusted Signing](https://learn.microsoft.com/azure/trusted-signing/).
يتطلب سجلًا تجاريًا للشركة عمره ثلاث سنوات فأكثر.

## التفعيل

لا تعديل في الكود. أضف الأسرار في المستودع:
**Settings ← Secrets and variables ← Actions ← New repository secret**

### خدمة Microsoft

| السرّ | القيمة |
|---|---|
| `AZURE_TENANT_ID` | من Azure |
| `AZURE_CLIENT_ID` | من Azure |
| `AZURE_CLIENT_SECRET` | من Azure |
| `AZURE_CODE_SIGNING_ACCOUNT` | اسم حساب التوقيع |
| `AZURE_CERT_PROFILE` | اسم ملف الشهادة |

### شهادة PFX

| السرّ | القيمة |
|---|---|
| `WINDOWS_CERT_BASE64` | ملف `.pfx` بترميز base64 |
| `WINDOWS_CERT_PASSWORD` | كلمة مرور الملف |

للتحويل إلى base64:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("cert.pfx")) | Set-Clipboard
```

بعد إضافة الأسرار، أي دفعة جديدة تُنتج مثبّتًا موقّعًا. البناء يتحقق من
التوقيع ويفشل إن كانت الشهادة مضبوطة لكن التوقيع غير صالح — فلا يصل
مثبّت محظور إلى الموظفين.

## حتى ذلك الحين

على جهاز يظهر فيه الحظر: **الإعدادات ← الخصوصية والأمان ← أمن Windows ←
التحكم في التطبيقات والمستعرض ← إعدادات التحكم الذكي في التطبيقات ←
إيقاف**.

⚠️ إيقافه لا رجعة فيه: لا يمكن إعادة تشغيله إلا بتثبيت ويندوز من جديد.
